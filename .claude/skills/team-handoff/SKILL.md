# 팀 인수인계 (킹오더 공통)

다른 사람이나 새 Claude Code 대화가 이 작업을 **이 문서만 읽고** 이어서 할 수 있도록 인수인계 문서를 작성합니다. 원본: 상위 폴더 `개발 협업/claude_skills/team-handoff/SKILL.md` (`공통규칙_넣기.mjs`가 각 저장소로 복사, 저장소에서 직접 수정 금지).

## 언제 쓰나

- 작업을 중간에 멈추고 나중에 이어서 할 때
- 작업을 다른 사람에게 넘길 때 (휴가·담당 변경·퇴사)
- 대화가 길어져 새 대화로 이어 가야 할 때

## 작성 전 확인

1. `git status`, `git branch --show-current`, `git log --oneline -5`로 현재 가지·커밋하지 않은 변경을 확인합니다.
2. 열린 PR이 있으면 번호를 확인합니다 (`gh pr list --author @me`, 도구가 없으면 생략하고 "PR 확인 필요"로 적음).
3. 이번 작업에서 실행한 시험 명령과 결과를 확인합니다. 실행하지 않았으면 "미실행"으로 적습니다.

## 파일 위치·이름

- `docs/인수인계/YYYYMMDD_<이니셜>_<내용>.md` (예: `docs/인수인계/20261117_hs_pos-refund.md`)
- 이니셜을 모르면 작업 가지 이름(`feature/<이니셜>-…`)에서 가져오고, 그것도 없으면 사용자에게 묻습니다.

## 문서 형식 (한글, 업무 표현)

```markdown
# 인수인계: <작업 이름>

- 작성일: YYYY-MM-DD
- 작성자: <이름(역할)>  → 받는 사람: <이름 또는 "미정">
- 저장소·가지: <저장소> / <feature/...>   PR: #<번호> 또는 없음
- 버전: <화면 버전 또는 해당 없음>

## 1. 목표
이 작업이 끝났을 때의 상태를 한 문단으로 적습니다 (지금 하던 세부 작업이 아니라 최종 결과).

## 2. 현재 상태
| 구분 | 내용 |
|---|---|
| 완료 | 동작 확인한 것 |
| 미완료 | 남은 것 |
| 문제 | 증상·오류 문구 그대로 |
| 시험 | `검증: <명령> → <결과>` 또는 미실행(이유) |
| 개발 DB | 실행한 SQL 파일 / 실행 안 한 SQL 파일 |
| 커밋하지 않은 변경 | 파일 목록 또는 없음 |

## 3. 관련 파일
| 파일 | 이유 |
|---|---|

## 4. 시도했으나 안 된 것 (가장 중요)
| 시도 | 안 된 이유 (원인) |
|---|---|

## 5. 현재 판단
다음에 할 방향과 그렇게 판단한 근거. 확인하지 못한 것은 "미확인"으로 표시합니다.

## 6. 다음 할 일 (순서대로)
1. 파일 경로·명령까지 구체적으로
2. ...

## 7. 주의 사항
- 관리자 확인이 필요한 것 (업체 실서버 시험, 운영 반영, 비밀값)
- 하지 말라고 정한 것, 업체 답변 대기 중인 것 (문의·답변 파일 위치)
```

## 작성 규칙

- 받는 사람은 이 대화를 보지 못했다고 생각하고 씁니다. "아까 그것" 같은 표현을 쓰지 않습니다.
- 구체적으로 씁니다. "결제 고치기"가 아니라 "`server/pay.mjs` 취소 처리에서 금액 비교가 문자열로 되어 있음 → 숫자 비교로 수정 필요".
- 오류 문구·시험 결과는 그대로 옮깁니다.
- 비밀값(`.dev.vars` 값, 키, 비밀번호)은 적지 않습니다. "`.dev.vars`의 `NICEPAY_SECRET_KEY` 필요"처럼 이름만 적습니다.
- 추측과 확인한 사실을 구분합니다.

## 작성 후

1. 문서를 커밋합니다: `[<프로젝트>][인수인계] <작업 이름>` (작업 가지에 함께 커밋하거나, 작업 가지가 없으면 `feature/<이니셜>-handoff-<내용>` 가지로)
2. 작업 가지를 GitHub에 올려 둡니다 (받는 사람이 이어서 받을 수 있게).
3. 사용자에게 짧게 알립니다: 문서 경로, 받는 사람이 새 대화에서 "`docs/인수인계/<파일>` 읽고 이어서 진행해줘"라고 하면 된다는 것.
